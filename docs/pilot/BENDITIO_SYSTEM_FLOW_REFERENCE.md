# Benditio System Flow Reference

Audience: developer and support team.

Malformed/unsupported payloads handled by provider result/status. | `tests/Feature/WhatsAppIncomingWebhookTest.php`, `tests/Feature/TelegramIntakeTest.php`, `tests/Feature/SimulatorIntakeTest.php`, `tests/Feature/MessagingIngestionServiceTest.php` |

| Fulfillment plan creation | `App\Services\Fulfillment\FulfillmentPlannerService::createDefaultPlan()` and `::parseIntentFromMessage()` | `Order`, message text | `FulfillmentPlan` with intent metadata and decision fields | Intent parsing or decision evaluation errors are logged; plan keeps defaults. | `tests/Feature/FulfillmentPlanTest.php`, `tests/Feature/FulfillmentIntentParserTest.php`, `tests/Feature/FulfillmentDecisionEngineTest.php` |
| Fulfillment intent parsing | `App\Services\Fulfillment\FulfillmentIntentParser::parse()` | order + natural language text | date, time window, delivery, payment, priority, confidence, metadata | Unclear text returns lower confidence and may leave fields null or ambiguous. | `tests/Feature/FulfillmentIntentParserTest.php` |

## Notes

- Use `routes/web.php` as the source of truth for route names.
- Do not treat placeholder provider behavior as a production integration.
- Do not use stale prompt text or old reports to infer current behavior.
