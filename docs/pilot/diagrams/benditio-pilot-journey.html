Benditio Pilot Journey

Flujo visual del piloto

Este recorrido resume cómo un mensaje entra, se entiende, se prioriza, pasa por la mesa operativa y termina despachado y completado. Cada etapa muestra la entrada del cliente, el comportamiento automático, la salida visible para el operador y una posible excepción.

Automatizado Acción del operador Revisión requerida Finalizado
1
✉

Cliente escribe

Entrada del cliente

El cliente envía un mensaje por WhatsApp, Telegram o Instagram.

Comportamiento automático

El mensaje entra al canal o al simulador y queda listo para procesarse.

Resultado visible

Aún no hay acción operativa; el pedido recién empieza su recorrido.

Excepción posible

El mensaje puede llegar vacío, duplicado o con un canal que todavía es placeholder.

2
◔

Benditio entiende

Entrada del cliente

Texto con productos, cantidad, fecha, hora o condiciones de entrega y pago.

Comportamiento automático

El parser extrae artículos y señales como hoy, mañana, pickup, delivery, SINPE o efectivo.

Resultado visible

El pedido muestra fecha, hora, método de entrega y método de pago.

Excepción posible

Si el texto es ambiguo, el sistema conserva una confianza baja o deja campos sin definir.

3
⚑

Benditio organiza y prioriza

Entrada del cliente

Pedidos del mismo cliente o de clientes frecuentes en canales distintos.

Comportamiento automático

El motor calcula prioridad, riesgo, SLA y posible duplicado de negocio.

Resultado visible

Los pedidos se ordenan en `DO NOW`, `NEXT` o `COMPLETED` según su estado.

Excepción posible

Un pedido puede quedar marcado como posible duplicado y requerir revisión humana.

4
⌂

Operador prepara

Entrada del cliente

El operador abre la tarjeta y revisa lo que pidió el cliente.

Comportamiento automático

La acción primaria cambia según el estado: confirmar, preparar o marcar listo.

Resultado visible

El panel lateral muestra artículos, cumplimiento, prioridad, duplicado y contexto del cliente.

Excepción posible

Si faltan datos o la tarjeta es ambigua, el operador debe revisar antes de avanzar.

5
✓

Pedido se despacha y completa

Entrada del cliente

El pedido ya fue validado, preparado y marcado listo para salir.

Comportamiento automático

Al despachar, el estado cambia a `Despachado` y el historial queda guardado.

Resultado visible

Tras refrescar, el pedido aparece en `COMPLETED` y sigue disponible para consulta.

Excepción posible

Si no persiste el estado o cambió el filtro, el pedido puede no verse donde se espera.
