# Safe anonymization for parser evaluation

Do not copy production rows or payloads into the repository. Select only the message text in an authorized local workflow, transform it with `App\Services\ParserQuality\DatasetAnonymizer`, manually review the result, then assign a new `PQI-*` case ID. The original message, database IDs, raw payload, and mapping from a case back to a message remain outside this dataset.

The anonymizer replaces emails with `[EMAIL]`, phone-like numbers with `[PHONE]`, Telegram usernames with `[TELEGRAM_USERNAME]`, explicit Telegram user/chat IDs with `[TELEGRAM_ID]`, order references with `[ORDER_NUMBER]`, address-like fragments with `[ADDRESS]`, and names after explicit identity phrases with `[PERSON]`. It retains product wording, quantities needed to evaluate an order, general channel/source type, category, and label notes that contain no identifiers.

Automatic detection cannot reliably recognize every personal name, free-form address, account number, or sensitive context. Manual review is mandatory. Remove the entire non-essential fragment when redaction is uncertain; reject the case if meaningful evaluation text cannot safely remain. The validator blocks obvious phones, emails, Telegram handles/IDs, order numbers, and address markers, but it is a guardrail rather than proof of anonymity.

Known production PII locations are `incoming_messages.raw_text`, `from_identifier`, `to_identifier`, `external_message_id`, and `payload_json`; `orders.raw_message_text`, `external_message_id`, and parsed payloads; `customers` name/phone/external ID; and `customer_identities` external user/chat IDs, username, phone, email, display name, and metadata. Relationships are organization → branch/customer/message; message → optional order; order → customer/items/products. No parser-evaluation exporter or anonymizer existed before this dataset mechanism. Existing seeders, fixtures, and baseline cases are test material and may be reused only with their `test` source type.
